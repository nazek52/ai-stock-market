# Этап 0 — предложения участника A

Статус: проект для согласования, 2026-10-14. Ответственный: участник A. Задачи: P0.1, P0.4, P0.5. Эти предложения не утверждают решения D1–D5 из `product-decisions.md`.

## P0.1. Рынок и аудитория

Рабочее обратимое допущение для проектирования интерфейса: первая версия показывает обыкновенные акции с основных площадок США — NASDAQ и NYSE. Базовая валюта первой версии — USD; каждая цена всё равно сопровождается валютой, которую вернул источник. Пересчёт валют и поддержка ETF, опционов и других рынков пока не планируются. Интерфейс на русском. Целевая аудитория — частные пользователи, которые следят за рынком и собственным списком акций. Сервис информационный: покупка, продажа и инвестиционные рекомендации не входят в сценарии.

Перед утверждением D1 владелец продукта должен подтвердить рынок, типы инструментов, язык, целевую аудиторию и необходимость пересчёта валют. Видимые названия, форматы чисел и набор тикеров должны быть конфигурируемыми, чтобы это допущение не закрепилось в серверном контракте.

## P0.4. Экраны и переходы

| Экран | Основное действие | Состояния для проектирования |
| --- | --- | --- |
| Вход и регистрация | Создать аккаунт или войти | Валидация, неверные данные, загрузка, истёкшая сессия |
| Дашборд | Оценить рынок и перейти к поиску | Загрузка, пустые данные, сбой одного источника, время обновления |
| Поиск | Найти инструмент по тикеру или названию | Пустой запрос, нет совпадений, квота, устаревший запрос |
| Акция | Посмотреть цену, график, профиль и новости | Неизвестный тикер, частичные данные, сбой виджета |
| Список отслеживания | Добавить или удалить акцию, открыть карточку | Пустой список, повторное действие, ошибка сохранения |
| Правила уведомлений | Создать, приостановить или удалить правило | Нет правил, некорректный порог, лимит, ошибка сохранения |
| Настройки | Изменить профиль, согласие на письма и часовой пояс | Ошибка сохранения, отключённая рассылка |

Переходы: вход → дашборд; дашборд → поиск → акция → список; список → акция или правила; из постоянной навигации доступны список, правила и настройки. Все личные экраны требуют сессии. Мобильная навигация должна давать доступ к тем же разделам и показывать текущий раздел.

## P0.5. Приёмка первой версии

1. Пользователь может зарегистрироваться, войти и выйти; после перезагрузки страницы личные данные остаются доступны только ему.
2. Поиск находит инструмент по тикеру и названию. Неизвестный тикер, пустой ответ, квота и сбой поставщика дают понятное состояние без падения страницы.
3. Страница акции и дашборд показывают источник и время обновления собственных данных; недоступность одного источника не скрывает доступные данные.
4. Добавление в список сохраняется после выхода и повторного входа; повторное добавление не создаёт дубль; чужой список недоступен.
5. Подписанный пользователь получает не более одного ежедневного выпуска за локальный календарный день. Отписанный не получает письмо; письмо содержит источники новостей и путь к настройкам.
6. Правило срабатывает только при выполнении подтверждённого условия по достаточно свежим данным. Повтор одного события не создаёт второе письмо. Частота проверок и допустимая задержка должны быть утверждены по D2 до приёмки.
7. Основные сценарии доступны с клавиатуры на узком и широком экране; для форм видны подписи, ошибки и состояние отправки.

Тестовые тикеры для предложения: `AAPL`, `MSFT`, `NVDA` (NASDAQ), `KO` (NYSE), `ZZZZINVALID` (неизвестный символ). Этот набор проверяет обе предложенные площадки и состояние «не найдено», но фактическое покрытие, формат символов и право использования данных нужно подтвердить с выбранным тарифом Finnhub. Для проверки изоляции нужны два отдельных тестовых аккаунта; реальные адреса в репозиторий не записываются.

Проверяемые переходы для P0.4: незалогиненный пользователь открывает личный экран → видит вход; после входа попадает на дашборд; поиск ведёт на страницу выбранной акции; из неё доступно добавление в список; из списка можно вернуться к акции; настройки доступны из постоянной навигации на ширине 375 и 1280 пикселей. Реализация этих переходов относится к следующим этапам и пока не проверялась.
