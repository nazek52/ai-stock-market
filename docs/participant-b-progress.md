Использовать src/contracts и docs/api-contract.md, handoff каждого этапа. Auth использует нативный JSON Better Auth, остальные маршруты — ApiResult. Все мутации с текущего origin; userId не передавать. UI показывает source=fixture и время данных, различает 400/401/404/409/429/502/503. В синтетический набор добавлен KO для сценария A. Перечень бирж остаётся предметом согласования D1: A предварительно указал NASDAQ/NYSE, адаптер допускает также CBOE/IEX. При объединении product-decisions.md сохранить подробные D2–D5 B. ## Что требуется для production

1. Владельцы аккаунтов, регион и бюджет хостинга/БД; HTTPS origin и домен.
2. Finnhub API key, подтверждённые права, покрытие/задержка/квота; проверить вместимость списка и polling при одновременной работе UI.
3. Проект Gemini, разрешённая модель и key.
4. Внешний SMTP, подтверждённый отправитель и домен; одна контролируемая доставка и согласованный шаблон A.
5. Inngest Cloud keys и регистрация подписанного HTTPS endpoint.
6. Секреты в secret manager/игнорируемом env, preflight/readiness, совместная приёмка A/B; только затем включение расписаний.

Подробная последовательность: production-deployment.md. Наличие кода и зелёных тестов не означает созданных облачных аккаунтов или выпущенного продукта.
