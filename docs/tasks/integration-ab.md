# Совместная интеграция A+B: локальная v1

Дата назначения: 2026-10-15. Решение владельца: объединить работу обоих участников в main и подготовить бесплатный демонстрационный проект без обязательных облачных аккаунтов. Документ относится к P0.2/P0.3, совместным handoff этапов 1-7 и P8.1-P8.5. Роль исполнителя этого изменения - B/planning; проверяющий - основной агент, пользовательскую приёмку выполняет A.

## Вход и границы

Вход: ветки A/B с интерфейсом, API, БД, заданиями и тестами; implementation-plan v1.1; уточнение владельца о нулевом бюджете. Рабочая интеграционная ветка - integration/ab-local-demo. Целевой main становится итогом после объединения, проверок и отправки основным агентом; до подтверждения не считать удалённый main обновлённым.

A сохраняет UI, адаптивность, доступность и пользовательские сценарии. B сохраняет серверные контракты, сессии/ownership, MongoDB, рыночный адаптер, уведомления и задания. Документационный агент меняет только README, основной план Markdown/PDF, product-decisions, local-demo и этот контракт; код, ветки, коммиты и GitHub объединяет основной агент.

## Проверяемый результат

1. Одно корневое Next.js-приложение использует UI A и защищённые API B; дублирующий frontend-проект не становится отдельным продуктом.
2. npm ci и npm run demo дают воспроизводимую локальную среду с ai_stock_market_demo, SMTP Mailpit и Inngest Dev без внешних ключей. Существующий env не перезаписывается; занятые порты не освобождаются удалением чужих процессов.
3. Собственные синтетические котировки/новости и детерминированная сводка помечены корректно; они не выдаются за Finnhub/Gemini. TradingView необязателен и имеет собственный источник.
4. Регистрация/локальное подтверждение адреса, поиск по имени/тикеру, постоянный список, согласие/preview, правила и явный сценарий синтетического crossing проходят через сервер, MongoDB и локальную почту.
5. Все 47 ID задач и роли сохранены в плане v1.2; полный PDF соответствует Markdown. Production-инструкция остаётся дополнительной, а отсутствие live-аккаунтов не блокирует приёмку демо.

## Проверки и передача

Основной агент выполняет npm run check, npm run test:integration и ручной показ по docs/local-demo.md; фиксирует фактические результаты, а не только ожидаемые критерии. Для Markdown проверяются относительные ссылки, отсутствие устаревшего URL/статуса и сохранность ID задач. Для PDF - полное извлечение текста, рендер страниц, визуальная читаемость и отсутствие обрезанных таблиц/строк.

Отчёт должен разделять: реализовано, проверено автоматически, проверено вручную локально, осталось необязательным будущим расширением. Отсутствие cloud production не является ошибкой локальной v1. Неработающий собственный экран, нарушение ownership или неподтверждённая заявленная доставка остаются дефектами независимо от бюджета.

Порядок завершения: агент документации передаёт файлы и PDF QA без коммита; основной агент принимает изменения, проверяет реализацию demo-сценария, завершает объединение в main и сообщает SHA/результаты. Самостоятельные изменения облачных аккаунтов и публикация сайта в задачу не входят.
