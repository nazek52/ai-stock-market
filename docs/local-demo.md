# Локальное демо A+B без сервисных аккаунтов

Решение владельца от 2026-10-15: бесплатная первая версия показывает совместную работу интерфейса A и сервера B на одном компьютере. Котировки/новости и сводка синтетические; хранилище, вход, проверка прав, API, почтовый транспорт и задания работают локально. Создавать облачные аккаунты не нужно.

## 1. Запуск

Установите Node.js 24 LTS и запустите Docker Desktop в режиме Linux-контейнеров. Откройте терминал в корне репозитория:

```sh
npm ci
npm run demo
```

Первый запуск скачивает npm-пакеты и Docker-образы. Команда создаёт игнорируемый .env.local только при отсутствии, использует его случайный auth-secret, поднимает MongoDB, Mailpit и Inngest и запускает Next.js. Существующие настройки не переписываются. Для процесса принудительно выбираются NODE_ENV=development, LOCAL_DEMO=true, отдельная ai_stock_market_demo, fixture market/AI, SMTP 127.0.0.1:1025, локальный Inngest; оба автоматических расписания выключены. Облачные ключи не используются.

| Что открыть | Адрес по умолчанию | Назначение |
| --- | --- | --- |
| Приложение | http://localhost:3000 | Единый интерфейс A с сервером B |
| Mailpit | http://127.0.0.1:8025 | Просмотр всех локальных писем |
| Inngest Dev | http://127.0.0.1:8288 | Локальные задания и их результаты |
| Liveness | http://localhost:3000/api/health | Процесс приложения отвечает |
| Readiness | http://localhost:3000/api/readiness | Доступна writable MongoDB replica set |

При занятом порте используйте `npm run demo -- --port 3100`; тогда приложение и ссылки входа открываются на localhost:3100, Mailpit/Inngest остаются на своих портах. Не переключайтесь между localhost и 127.0.0.1 для самого приложения: cookie сессии и origin привязаны к выбранному адресу. Скрипт не завершает чужие процессы.

## 2. Показ пользовательского пути

1. Откройте приложение и зарегистрируйтесь с вымышленным адресом, например demo@example.test. Используйте пароль не короче 12 символов. Никакого внешнего почтового ящика создавать не требуется.
2. Откройте Mailpit и письмо подтверждения. Перейдите по ссылке, вернитесь в настройки /settings и обновите состояние адреса. Если письмо не видно, используйте повторную отправку в карточке подтверждения. Локальный вход разрешён для разработки, однако для сводки и уведомления нужен подтверждённый адрес.
3. В /search введите AAPL либо Apple. Откройте карточку, проверьте метку синтетических данных и время. Другие примеры: MSFT/Microsoft, NVDA/Nvidia, KO/Coca-Cola. Названия - поисковые псевдонимы, значения не являются реальными котировками.
4. Добавьте акцию в /watchlist, обновите страницу. Выйдите и войдите снова: запись сохраняется в демобазе. Повторное добавление не создаёт дубль. Второй аккаунт видит свой список.
5. В /settings включите согласие на сводку, сохраните часовой пояс и время. Нажмите «Сформировать предпросмотр». Ожидается помеченный тестовый текст со ссылками на источники. Preview не отправляет письмо и не обновляет lastSentAt; это отдельная проверка от SMTP-доставки.
6. В /alerts создайте правило AAPL, например «цена выше 100 USD», затем попробуйте паузу/возобновление. Сохранение и ошибки приходят от защищённого серверного API. Одно создание правила ещё не означает срабатывание: первое наблюдение задаёт baseline, fixture-цена не меняется автоматически.
7. Откройте /demo и нажмите «Запустить 99 → 101 и отправить в Mailpit». Сценарий создаёт отдельное временное правило вашего аккаунта и проводит синтетический переход 99 -> 101 при пороге 100; существующие правила не изменяются. После фиксации события и локальной отправки временное правило удаляется. Используется обычный notification sender, глобальные расписания не включаются. Считайте отправку подтверждённой только при успешном результате и наличии письма в Mailpit; неопределённый/ошибочный статус требует проверки журнала.
8. В /demo нажмите «Отправить ежедневную сводку в Mailpit». Ожидается статус sent и отдельное письмо сводки с источниками. Ручной запуск использует текущую локальную дату вашего часового пояса и пропускает ожидание выбранного времени; подтверждение адреса и согласие сохраняются обязательными. Нажмите повторно: ожидается duplicate, второго письма за эту дату нет. Preview и реальная сводка имеют разные журналы.
9. В доставленной сводке откройте ссылку «Отключить ежедневную сводку». Открытие показывает подтверждение и ещё не меняет согласие. Подтвердите отключение кнопкой на странице. Повторите отправку из /demo: ожидается skipped и сообщение «Рассылка отключена», нового письма нет. Альтернативная кнопка отключения есть в /demo и настройках. Повторное включение в тот же день не создаёт второй выпуск.

Экран /demo предназначен только для явно включённого локального режима с fixture-источником, loopback SMTP и выключенными расписаниями. Обычный dev и production не должны превращать его в произвольный API отправки. Полный успешный показ фиксируется в итоговом handoff; описание сценария само по себе не является отчётом о пройденной проверке.

## 3. Что здесь синтетическое

Доступный набор: AAPL, MSFT, NVDA, AMZN, TSLA, BRK.B, KO. DTO используют source=fixture и названия Synthetic ... Company; символы удобны для навигации, а цена и новость созданы для теста. ZZZZZ имеет корректную форму, но отсутствует в наборе и даёт NOT_FOUND; ../AAPL - неверный ввод. Имена, цены и времена не нужно сравнивать с биржей.

AI_MODE=fixture детерминированно берёт заголовки выбранных новостей с привязкой к источникам. Это воспроизводимая замена внешнего AI для демонстрации потока данных, не генерация Gemini и не прогноз. SMTP Mailpit принимает сообщения локально, в том числе на example.test; они не уходят к реальным получателям.

TradingView загружается отдельно из Интернета и показывает собственные данные внешнего виджета. Это не источник событий локальных правил. При блокировке сети виджета собственные страницы и API продолжают работать. Пакеты/образы требуются при первом запуске, но после установки серверные сценарии не требуют обращений к облачным провайдерам.

## 4. Остановка и повторный запуск

Ctrl+C останавливает только Next.js, запущенный текущей demo-командой. MongoDB, Mailpit и Inngest остаются доступны, чтобы общие сервисы не исчезли у второго участника. Для явной остановки:

Только фоновые задания можно остановить командой `npm run services:jobs:stop`: MongoDB и Mailpit продолжат работать. Повторный `npm run demo -- --port 3100` восстановит задания и правильный адрес callback для выбранного порта.

```sh
npm run services:down
```

MongoDB volume сохраняется; повторный npm run demo открывает ту же демобазу. Mailpit может очистить временную почту при пересоздании контейнера. Удаление volume не нужно для обычного запуска. Ошибка занятого порта или остановленный Docker исправляются выбором другого порта/запуском Docker, без удаления чужих процессов или данных.

Обычная разработка: `npm run dev` использует собственный .env.local. Ручные локальные сервисы описаны в [local-services.md](local-services.md). Для совместного показа используйте demo-команду, чтобы случайные внешние ключи не определяли режим.

Демосервер принимает localhost по IPv4 и IPv6. Если открыта старая вкладка с ошибкой соединения, дождитесь строки готовности в терминале и обновите `http://localhost:3100/register` (либо адрес выбранного порта). Для `npm run check` сначала остановите свой demo через Ctrl+C: dev и build используют общий каталог `.next`. После проверки запустите demo снова; аккаунт и список сохранятся в MongoDB.

## 5. Проверки и роли

A проверяет связность экранов, подписи, клавиатуру и узкий/широкий экран. B проверяет ownership, записи в БД, события, идемпотентность и остановку. Автотесты: npm run check и npm run test:integration; интеграционные тесты используют отдельную временную replica set и не очищают пользовательскую демобазу. Зафиксируйте отдельно: команды/коды завершения, ручной UI-прогон, письмо в Mailpit и известные ограничения.

Цель публикации исходников - один проверенный main с историей работы A+B. Облачное production-размещение остаётся отдельным необязательным расширением по [production-deployment.md](production-deployment.md).
