## Среда и метод

Локальный Next.js, MongoDB, Mailpit, Inngest; синтетические данные. Облачные сервисы и внешняя SMTP-доставка не подключались. Проверка через настоящий встроенный Chromium: доступное дерево, DOM-геометрия, скриншоты, клавиатурные действия. Тестовые записи принадлежат отдельному синтетическому аккаунту; два созданных для проверки правила удалены, согласие на сводку возвращено в выключенное состояние.

Для каждого размера проверялся фактический `innerWidth`, ширина документа и выход видимых элементов main/header за границы окна. Дополнительно проверены имена собственных кнопок/ссылок/полей, существование целей aria-labelledby/aria-describedby, повторяющиеся id и собственные кнопки меньше 24 px. Это ограниченный набор проверок DOM, а не запуск axe или сертификация WCAG.

### Масштаб

Настоящий browser zoom 200% в этом инструменте не подтверждён: Ctrl+plus/Ctrl+equal не меняли innerWidth и devicePixelRatio; доступен только viewport override. Отдельно выполнен reflow при 720 CSS px — ширине содержимого окна 1440 px при двукратном увеличении. Это проверяет перенос в соответствующем пространстве, но не заменяет проверку самого zoom, text-only zoom или растеризации. Ручной 200% в обычном браузере остаётся явным ограничением инструмента, без объявления ложного PASS. На 320 CSS px интерфейс проверен непосредственно. Ориентир для reflow: [W3C 1.4.10](https://www.w3.org/WAI/WCAG21/Understanding/reflow).

Видимая рамка проверена в тёмной теме браузера. Светлая и тёмная палитры проверены расчётом основных CSS-пар: в светлой теме старый muted-текст на фоне давал 4.35:1, новый — 5.36:1. Усилены границы полей в обеих палитрах; рамка использует тематическую переменную ring. Это не измерение каждого пикселя iframe. Ориентир контраста: [W3C 1.4.3](https://www.w3.org/TR/WCAG22/#contrast-minimum).

## Ошибки API и восстановление

Для UI ошибок использован временный локальный HTTP-прокси на 3111, пересылающий HTML/assets настоящего Next.js и заменяющий ответы выбранных API. Записи через него заблокированы. Прокси остановлен после проверки; приложение продолжает работать непосредственно на 3100. Это контролируемые ответы/обрывы соединения, а не реальный сбой поставщика или глобальный offline браузера.

- `/watchlist`, `/alerts`, `/settings` (обе формы): 401, 429, 503 и обрыв соединения — 12 проверок. Понятное сообщение, доступное действие повтора/входа, отсутствие обрезания на 320 px.
- Поиск, собственная котировка на карточке и котировка обзора: 429 и 503 — ещё 6 проверок. Ошибка собственной цены не подменяется внешней ценой TradingView; в карточке добавлен alert для объявления ошибки.
- Пустой список наблюдения проверен управляемым ответом `data: []`; после восстановления API сохранённый AAPL снова отображается.
- Повтор профиля/рассылки после обрыва: формы загрузились, фокус направлен в первое поле соответствующей формы.
- Неизвестный тикер проверен настоящим API 404. Отсутствующее правило, изоляция владельца, неподтверждённые изменения и лимиты дополнительно проверяются интеграционными тестами; отдельный ручной потерянный ответ после фактического commit БД здесь не заявляется.

## Исправленные дефекты

1. Длинные кнопки /demo обрезались `overflow-hidden` карточки. Текстовые кнопки теперь переносят текст, имеют автоматическую высоту и ограничение ширины.
2. Длинная ссылка в загруженном preview создавала min-content ширину около 1450 px. Вложенные grid ограничены `minmax(0,1fr)`, PRE переносит длинные строки и доступен для прокрутки клавиатурой.
3. Skip-link не задавал надёжную цель фокуса; main получил tabIndex=-1. Все основные маршруты получили отдельный document.title.
4. AppShell в client-странице акции читал серверный LOCAL_DEMO и выдавал разный список навигации при SSR/hydration. Сервер передаёт публичный boolean через контекст; секретов и новых env нет.
5. Удаление правил теряло фокус, не поддерживало Escape; действия одинакового символа имели одинаковые имена. Список акций удалял запись без подтверждения. Добавлены именованные inline-подтверждения, Escape и возврат фокуса.
6. Очистка поиска, сохранение форм и асинхронные операции теряли фокус после удаления/disabled элемента. Добавлены результат/восстановление фокуса и объявления успеха/ошибки.
7. Страница отписки не имела viewport/main и после form POST показывала JSON. Добавлены самостоятельные HTML-состояния; JSON-контракт для программных клиентов сохранён, CSP остаётся строгой, GET не меняет согласие.
8. Светлый muted-текст, статус и границы полей имели слабый контраст. Цвета скорректированы; topbar переносит сообщения/действия вместо фиксированной высоты.
