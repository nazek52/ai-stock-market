# Приёмка участника A: правила уведомлений

Дата: 2026-10-14. Ветка: `feat/a-stage-7-alerts`. Задачи A: P7.1, P7.6. Серверные P7.2–P7.5 и точный контракт ответа передаёт B.

## Экран P7.1

Пользователь с сессией создаёт правило по символу, направлению пересечения и порогу в USD, видит сохранённое правило после обновления страницы, меняет порог/направление/период подавления, приостанавливает и возобновляет правило, удаляет его с подтверждением. Каждое изменение считается успешным только после ответа API. При ошибке форма сохраняет введённые значения, а неподтверждённое изменение не отображается как сохранённое. Пустой список, истёкшая сессия, валидация, квота и временный сбой имеют различимые сообщения.

Частота проверки должна отражать действующий серверный режим B. До подтверждения B экран не обещает немедленное срабатывание. Источник цены, время последней проверки, свежесть котировки и период подавления повторов требуют полей в API; текущий `PriceAlertRule` содержит только `lastTriggeredAt`. Это открытый контрактный пробел для интеграции.

## Сценарии P7.6 с B

| Ситуация | Ожидаемое наблюдение |
| --- | --- |
| Переход свежей цены через порог в рабочую сессию | Одно событие и одно принятое почтовым провайдером письмо; `lastTriggeredAt` отражает подтверждённое событие. |
| Нерабочий день биржи, отсутствующая или старая (>900 с от `observedAt`) котировка | Письмо не создаётся, последнее срабатывание не меняется; UI не выдаёт правило за сработавшее. |
| Повтор запуска задания и повтор чтения того же пересечения | Не возникает второго события/письма в период подавления. |
| Правило изменено или приостановлено между чтением и проверкой | Старый вариант правила не отправляет уведомление. |
| Правило возобновлено, затем возникло новое пересечение | Событие рассматривается по новому состоянию правила с соблюдением периода подавления. |
| API сохранения/удаления недоступен или вернул отказ | UI оставляет подтверждённое сервером состояние и показывает действие для повтора. |

Измерить `scheduledAt`, `startedAt`, `observedAt`, `evaluatedAt`, `providerAcceptedAt` и задержку на фактическом источнике. Проектные 300 с обхода и 900 с допустимого возраста котировки из `docs/service-setup.md` пока не являются проверенной гарантией. Приём письма провайдером не подтверждает доставку в ящик.

## Условия ручной проверки

Нужны работающие MongoDB, тестовый аккаунт, подтверждённый адрес, почтовый транспорт и либо живой рыночный источник, либо управляемые фикстуры перехода. В текущей облачной среде загрузка MongoDB с `fastdl.mongodb.org` блокируется прокси 403; черновик сетевой конфигурации ожидает публикации. До выполнения этих условий P7.6 не считается принятой.
