# Передача P4.2: нормализация символов и результатов, участник B

Дата: 2026-10-14. Основание: завершённый адаптер P3.3, коммит `0f1de52`. Реализация нормализации технически входит в единый клиент этапа 3; этот этап закрепляет её отдельными проверками и контрактом для подключения участником A.

Статус: серверная часть P4.2 и HTTP-маршруты поиска, quote, company, news реализованы и проверены на синтетических/mock-данных. Экраны P4.1/P4.3/P4.4/P4.5 — участник A. Отсутствует подтверждение live API без аккаунта/ключа и утверждённой лицензии.

Входы: `symbolSchema`, `stockSearchQuerySchema`, D1 US equity/USD, общий `ApiError`. Тип `StockSearchResult` возвращает `symbol`, `companyName`, фактическую `exchange`, `instrumentType: "equity"`. `StockCompany` добавляет валюту, отрасль, website/logoUrl, капитализацию и `source`. Часовой пояс не участвует в идентификации символа.

Символ обрезается по краям и переводится в верхний регистр. Точки и дефисы сохраняются: BRK.B и BRK-B не объединяются по предположению. Регулярное выражение не доказывает существование инструмента: сервер проверяет US common-stock lookup и профиль компании. Неподдерживаемый рынок, валюта, тип или отсутствующая компания дают `NOT_FOUND`; неверная форма входа — `INVALID_INPUT` на HTTP-границе. Ошибки провайдера и квот сохраняют свои типы.

Поиск ограничен пятью результатами и шестью внешними запросами при холодном кэше. Повторный запрос с другим регистром использует тот же кэш. Биржа не угадывается по символу; берётся из проверенного профиля. Штаб-квартира за пределами США сама по себе не определяет листинг. Для полного отсутствия котировки или показателя UI показывает отдельное пустое состояние и не подставляет ноль.

Изменённые файлы этапа: `src/server/market/normalization.ts`, `tests/market/normalization.test.ts`, этот handoff. Уточнено различие между отсутствующей компанией (пустой объект) и невалидным ответом-массивом. Проверки: `npm test -- tests/market/normalization.test.ts` — 6 тестов успешно; `npm run typecheck` — успешно. Предыдущий полный `npm run check` для P3.3 прошёл: 76 тестов, lint, типы и production build.

HTTP-маршруты требуют серверную сессию, возвращают no-store и X-Market-Data-Mode, ограничены 60 запросами/мин на пользователя. Общий сетевой permit Finnhub подключён в этапе 3. Три интеграционные проверки на реальном MongoDB подтверждают 401 без сессии, результаты синтетического рынка, различие 400 и 404. Исправлен тип документа request_windows в интеграционной проверке permit. Полная проверка этапа: 82 unit-теста, lint, typecheck и production build.

Следующий шаг: A использует опубликованные DTO для результатов поиска/страницы акции, отражает 429 и NOT_FOUND, source и время получения, запускает интеграционную проверку после handoff.
