Дата: 2026-10-14. Основание: `38d3ebf` (этап 1); независимая рабочая копия `b-market-adapter`. Проверяющий — основной агент, получатель контрактов — участник A. Область: `src/server/market/**`, тип `StockCompany` в `src/contracts`, `tests/market/**`. Вход: D1 US stocks, обратимые параметры D2, API-контракты этапа 1.

Результат: `MarketClient` предоставляет `quote(symbol)`, `company(symbol)`, `search(query)`, `news(symbol)`, `marketNews()`. Фабрика `createMarketClient(options)` позволяет внедрить fetch, часы и атомарный общий бюджет; `getMarketClient()` читает конфигурацию лениво. `setMarketSharedBudget(consume)` устанавливается один раз до первого создания singleton. Callback `consumeSharedBudget(): Promise<releaseAsync | void>` должен атомарно резервировать общий лимит и единственный сетевой слот; транспорт вызывает полученную функцию release в finally. Корневой агент подключает реализацию на MongoDB после этапа 2. По умолчанию бюджет/конкурентность ограничены внутри одного клиента, поэтому для нескольких процессов общий callback обязателен.

## Фактическое поведение

- Внешние запросы идут только на `https://finnhub.io/api/v1`, ключ — в `X-Finnhub-Token`, redirects запрещены. Таймаут получения заголовков и тела — 5 секунд, предел JSON — 1 МиБ. Текст ошибки провайдера и URL с секретом не возвращаются и не логируются.
- Локальный лимит — максимум 30 запросов за скользящую минуту, одновременно один запрос, очередь до 32. `429` учитывает bounded Retry-After (1–3600 с); нет автоматического бесконечного повтора. `401/403` означает неправильный доступ к провайдеру (`SERVICE_UNAVAILABLE`), `404` — `NOT_FOUND`, сеть/невалидный JSON/данные — `UPSTREAM_UNAVAILABLE`.
- Кэш до 256 успешных записей: котировки/поиск/новости на `MARKET_CACHE_SECONDS` (60 с по умолчанию), компании на час. Ошибки не кэшируются, одновременные одинаковые запросы объединяются, каждый получатель получает копию данных. Просроченный ответ не подменяет свежий после ошибки поставщика.
- Для прямой котировки: проверка точного типа `Common Stock` через US lookup, профиль компании с USD и поддерживаемой US-биржей, затем котировка. Холодная котировка требует до 3 сетевых запросов, повтор после истечения только котировки — 1. Поиск выдаёт до 5 проверенных результатов, холодный поиск требует до 6 запросов; при медленном провайдере они последовательно занимают до 30 секунд. HTTP-интеграция должна учитывать этот предел.
- `observedAt` берётся только из timestamp котировки. Отсутствующее время не заменяется текущим; допускается до 60 с рассогласования часов в будущем. Пропущенные показатели — null. `fetchedAt` фиксирует получение. Проверка устаревания для уведомлений принадлежит этапу 7.
- Компания возвращает название, биржу, отрасль и безопасные web/logo URL, капитализацию в единицах USD (поле Finnhub переводится из миллионов). Значения опциональных полей могут отсутствовать. Внешние URL только HTTP/HTTPS без credentials; приложение их не загружает сервером.
- Новости: последние 7 UTC-дней по компании или общий `category=general`; максимум 20 уникальных материалов, ISO-время, проверенные ссылки. Невалидные отдельные статьи отбрасываются. Пустой результат допустим; отсутствие новостей не заменяется выдуманными событиями.
- `fixture` — явный режим, собственные синтетические данные, метка source `fixture`. Отсутствующий live-ключ вызывает ошибку конфигурации, автоматической подстановки фикстур нет. Фикстуры: AAPL, MSFT, NVDA, AMZN, TSLA, BRK.B; цены и новости демонстрационные.

## Официальные источники

Дополнение интеграции root: фабрика по умолчанию использует `acquireMarketPermit` на MongoDB. Скользящее окно 60 с общее для всех процессов и lease 15 с ограничивают бюджет и единственный сетевой слот. Кэш по-прежнему локален процессу; дубли между процессами тратят общий бюджет. В fixture-режиме permit не вызывает БД. Добавлены интеграционные проверки конкурентного счётчика, владения lease и скользящего окна на границе минуты.
