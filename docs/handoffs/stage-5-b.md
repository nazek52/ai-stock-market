# Передача P5.1/P5.2: список отслеживания, участник B

Основание: stage-4/b-stock-api. Вход: текущая серверная сессия, watchlistAddSchema, проверенный StockCompany из рыночного адаптера. Коллекция watchlist_items содержит userId, symbol, companyName, createdAt; уникальный индекс (userId, symbol). Digest читает этот же контракт.

GET /api/watchlist возвращает собственные записи по времени создания. POST принимает только symbol, нормализует и подтверждает компанию на сервере; новая запись — 201, повтор — 200 с тем же DTO. DELETE /api/watchlist/:symbol идемпотентен и всегда фильтрует владельца. Мутации требуют Origin и действительную сессию, ограничены 60/мин на пользователя.

Лимит 50 записей обеспечен счётчиком и транзакцией MongoDB replica set, одновременно с добавлением/удалением. Уникальный индекс защищает от дублей, транзакции откатывают счётчик при ошибке. Чужой userId не принимается ни одним маршрутом. Котировки и новости в записи не сохраняются.

Зона A: кнопки, состояния загрузки/ошибки, экран списка и сверка оптимистичных изменений после ответа сервера. Не считать запись сохранённой до ответа POST. При CONFLICT показать ограничение списка. При удалении deleted:false повтор допустим.

Проверки: 10/10 интеграционных тестов на настоящем MongoDB replica set прошли: две сессии, изоляция, поддельные cookie, CSRF, строгий JSON, неизвестный символ, нормализация, 15 одновременных добавлений одного символа, гонка за последним местом, освобождение места после удаления и сохранение после нового входа. Lint, typecheck, 82 unit-теста и production build входят в полный gate этапа. Настоящий Finnhub требует внешнего аккаунта и подтверждения условий D2. В fixture режиме доступны только явно синтетические символы.
