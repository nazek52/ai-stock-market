## Журнал P8.1

Записать окружение и commit SHA, режим рынка (fixture/Finnhub), аккаунты A/B, время UTC, тестовый символ, способ получения почты и идентификаторы событий/писем. Не помещать в журнал токены, адреса пользователей или секреты.

| Шаг | Подтверждение | Результат/время/ссылка на свидетельство |
| --- | --- | --- |
| Регистрация и подтверждение адреса | Сессия создана только при разрешённом сервером состоянии; ссылка подтверждения одноразовая | Не проверено |
| Поиск акции | Символ, название, источник и режим fixture/live различимы | Не проверено |

| Сводка тестовому адресату | Источники корректны, одно письмо принято SMTP-провайдером; отписанный адрес не получает выпуск. Dev preview отдельно и доставки не подтверждает | Не проверено |

Браузерный UI не является доказательством доставки в почтовый ящик.

## Матрица P8.3

- Проверить `/`, `/search`, `/stocks/AAPL`, `/watchlist`, `/alerts`, `/settings`, `/login`, `/register`, `/reset-password` на ширине 320, 768 и 1440 px и масштабе 200%: без горизонтальной потери действий и обрезанных сообщений.
- Пройти Tab/Shift+Tab, Enter/Space и Escape без мыши: видимый фокус, порядок навигации, доступный текст кнопок, подписи полей, фокус на ошибке, пропуск к содержимому, подтверждения удаления.
- Для личных экранов проверить применимые состояния: пустой список, истёкшую сессию, неверные данные, 429, 503 и сетевой сбой; 404 проверить на неизвестном символе и отсутствующем правиле. Неподтверждённое изменение не должно выглядеть сохранённым. Проверить повторное открытие после восстановления API.
- Для котировок и новостей проверить квоту, устаревшие данные, отсутствие цены, выходной день и явную метку синтетического источника. Данные TradingView не должны подменять время собственной котировки.
- Зафиксировать `npm ci`, `npm run check`, `npm run test:integration`, production audit и результат CI на точном commit SHA. Интеграционный прогон требует MongoDB.
