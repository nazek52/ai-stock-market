# Локальные сервисы без внешних аккаунтов

Задача P1.4, участник B. Node.js 24 LTS и зависимости проекта должны быть установлены командой `npm ci`. Внешний аккаунт MongoDB, Docker и API-ключи для этого способа запуска не нужны. Это среда разработки без сетевой аутентификации и резервного копирования; для production она не предназначена.

## MongoDB без Docker

Из корня репозитория выполнить:

```sh
npm run setup:local
node scripts/mongo-local.mjs
```

`setup:local` создаёт `.env.local` со случайным секретом только при отсутствии файла. Сам `mongo-local.mjs` не читает и не изменяет `.env.local`, не принимает внешний URI и запускает только локальный `mongod`.

При первом запуске `mongodb-memory-server` 11.3.0 скачивает бинарный MongoDB 8.0.16 для текущей платформы. Требуются доступ к серверу загрузки MongoDB, свободное место и время на загрузку/распаковку. Бинарник кэшируется в игнорируемой папке `.local/mongodb-binaries`; база хранится в `.local/mongodb` с движком WiredTiger. Несмотря на название библиотеки, этот launcher использует постоянный `dbPath`, а не временную БД в памяти.

После сообщения `Local MongoDB ready` в другом терминале запустить приложение:

```sh
npm run dev
```

Ожидаемые настройки приложения из `.env.example`:

```dotenv
MONGODB_URI=mongodb://127.0.0.1:27017/ai_stock_market?replicaSet=rs0&directConnection=true
MONGODB_DATABASE=ai_stock_market
```

Launcher поднимает replica set `rs0` с одним участником и слушает только `127.0.0.1:27017`. Если порт занят, процесс завершится с ошибкой и не подключится к уже работающей БД. Остановите другой локальный экземпляр своим обычным способом или используйте уже подготовленную среду после проверки её владельца; одновременно Docker MongoDB и этот launcher не запускаются.

Остановка — Ctrl+C в терминале MongoDB. Обработчики SIGINT/SIGTERM вызывают `stop({ doCleanup: false, force: false })`; дождитесь сообщения об остановке. При сигнале во время начальной загрузки launcher ждёт завершения запуска и затем останавливает сервер. Не закрывайте окно принудительно во время этого ожидания. Повторная команда `node scripts/mongo-local.mjs` открывает те же файлы, поэтому аккаунты и настройки разработки сохраняются. Насильственное завершение процесса или выключение компьютера не позволяет гарантировать штатную остановку.

`.local/` исключена из Git. Launcher не удаляет БД при остановке, ошибке или повторном запуске. Данные этого способа запуска и Docker volume независимы; переход между ними не переносит аккаунты автоматически. Не кладите в этот стенд реальные персональные данные. Интеграционные тесты используют отдельный временный replica set и не должны указывать на этот постоянный адрес.

## Docker как альтернатива

Если Docker Desktop установлен и engine запущен, вместо `mongo-local.mjs` выполнить:

```sh
npm run services:up
```

`compose.yaml` поднимает MongoDB `mongo:8.0` и Mailpit `axllent/mailpit:v1.27`. MongoDB доступна на `127.0.0.1:27017`, Mailpit SMTP — `127.0.0.1:1025`, интерфейс писем — `http://127.0.0.1:8025`. Для остановки:

```sh
npm run services:down
```

Docker volume MongoDB сохраняется при этой команде. `down -v` удаляет volume и не является обычным способом остановки.

## Mailpit без Docker на Windows x64

В отдельном терминале PowerShell 7.4 или новее выполнить:

```powershell
pwsh -File scripts/mailpit-local.ps1
```

Launcher скачивает официальный Windows x64 ZIP Mailpit **v1.31.5** в `.local/mailpit/v1.31.5`, проверяет SHA256 перед каждой распаковкой и запуском. Версия была последней стабильной при проверке 2026-10-14. Закреплённый checksum `9637e21c02b33185fe69268ba05317152a5d8ac7877115e8a70e29b7e199e8dc` взят из `digest` официального [GitHub release asset API](https://api.github.com/repos/axllent/mailpit/releases/tags/v1.31.5); отдельного `checksums.txt` в этом release нет. Ошибка загрузки или checksum останавливает запуск; непроверенный архив не исполняется. Обновление версии требует явного обновления версии и checksum в скрипте.

Mailpit стартует скрытым дочерним процессом; launcher остаётся в терминале, сообщает его PID и проверяет готовность через `http://127.0.0.1:8025/api/v1/info`. SMTP слушает только `127.0.0.1:1025`, интерфейс — только `127.0.0.1:8025`. Если один из портов уже занят, launcher завершается, сохраняя существующие процессы. Наследуемые переменные `MP_*` очищаются только в окружении дочернего Mailpit; relay, forwarding, webhooks и автоматическая проверка версии не включаются. Настройки и секреты `.env.local` скрипт не читает и не меняет.

Остановка — Ctrl+C в терминале launcher. Блок `finally` останавливает только созданный этим запуском процесс и удаляет его PID-файл `.local/mailpit/mailpit.pid`. Он не ищет и не завершает чужие процессы по имени или порту. SQLite-файл с перехваченными письмами `.local/mailpit/mailpit.db` и журнал `.local/mailpit/mailpit.log` сохраняются; `.local/` игнорируется Git. Сохраняйте только синтетическую тестовую почту. При принудительном закрытии терминала штатное выполнение `finally` не гарантируется.

MongoDB и Mailpit запускаются независимо. По умолчанию `EMAIL_TRANSPORT=stream`, `EMAIL_ENABLED=false`, оба расписания выключены — для разработки аккаунтов почтовый сервер не нужен. Для ручного перехвата тестовых писем в Mailpit задайте в `.env.local` `EMAIL_TRANSPORT=smtp`, `SMTP_HOST=127.0.0.1`, `SMTP_PORT=1025`, `SMTP_SECURE=false`; включение `EMAIL_ENABLED` применяет текущий адаптер и требует отдельной проверки его поведения. Письмо в Mailpit не доставляется внешнему адресату. Production-отправка и фоновые задачи требуют отдельной конфигурации.

API библиотеки проверен по установленным `MongoMemoryReplSet.d.ts`/`.js` версии 11.3.0; официальное описание `dbPath`, запуска replica set и остановки: [mongodb-memory-server](https://github.com/typegoose/mongodb-memory-server).
